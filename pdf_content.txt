⼀、实验⽬的 
1. 深入理解操作系统中进程调度的基本原理和重要性 
2. 掌握多种经典调度算法的设计思想和实现方法： 
o 默认调度（随机选择） 
o 轮转调度（Round Robin, RR） 
o 优先级调度（Priority Scheduling） 
o 先来先服务调度（First Come First Served, FCFS） 
o 静态多级队列调度（Static Multi-Level Queue, SML） 
3. 通过实现上述调度算法，加深对操作系统内核的理解 
4. 设计合理的测试场景，定量分析不同调度算法的性能特点和适用场景 
5. 理解调度算法在公平性、响应性、吞吐量等方面的权衡

3.1.2 轮转调度算法（RR） 
实现思路： 记录上一次调度的位置，从该位置向后轮转选择下一个可运行进程。 
 

---PAGE---
5 
 
轮转算法可以让所有进程公平地获得CPU 处理的机会，不识别优先级，是最公平的算
法，可以比较好的避免某个进程垄断一整个CPU。 
 
3.1.3 优先级调度算法（Priority） 
实现思路： 遍历进程表，选择优先级数值最小（即优先级最高）的可运行进程。 
 
优先级调度算法会让优先级较高的进程先获得CPU，适合实时系统等对优先级要求高的
场景。 
3.1.4 先来先服务调度算法（FCFS） 
实现思路： 遍历进程表，选择创建时间最早的可运行进程。 

---PAGE---
6 
 
 
先来先服务算法按照顺序进行调度，对短作业可能不够友好，容易产生车队效应。 
3.1.5 静态多级队列调度算法（SML） 
实现思路： 按优先级将进程分为三个队列层级，优先调度高层队列；同层内采用轮转。 
优先级分层： 
• 
高层：优先级 1–6 
• 
中层：优先级 7–13 
• 
低层：优先级 14–20 

---PAGE---
7 
 
 
静态多级队列调度算法结合了优先级调度和轮转调度的优点，既可以保证高优先级任务的
快速响应，也可以保证公平性。

3.2.1 工作函数定义 
#define CPU_WORK 500000  // CPU 基准工作量 
#define IO_WORK 20       // IO 基准次数 
CPU 密集型工作： 
void cpu_work(int work) { 
  int i, j; 
  volatile int sum = 0;  // volatile 防止编译器优化 
  for (i = 0; i < work; i++) { 
    for (j = 0; j < 100; j++) { 
      int x = i * j + (i ^ j); 
      x = (x << 1) ^ (x >> 1); 
      sum += x; 
    } 
  } 
} 
IO 密集型工作： 
void io_work(int rounds) { 
  int i, fd; 
  char buf[] = "io test\n"; 
  for (i = 0; i < rounds; i++) { 
    fd = open("io_test", O_CREATE | O_WRONLY); 
    if (fd >= 0) { 
      write(fd, buf, sizeof(buf) - 1); 
      close(fd); 
    } 
    sleep(15);   
  } 
} 
交互型工作： 
void interactive_work(int rounds) { 
  int i; 
  for (i = 0; i < rounds; i++) { 
    cpu_work(CPU_WORK / 50);   
    sleep(10);                 
  } 
}

五、结果分析 
5.1 各调度算法特性分析 

---PAGE---
12
 
（1）DEFAULT（随机调度） 
分析： 
• 
场景1（车队效应） 
o 长作业就绪时间极短（1–4 ticks），因为最先创建且在进程表前端 
o 短作业就绪 16 ticks，必须等长作业执行后才能获得 CPU 
o 随机调度倾向于选择进程表前端的进程 
• 
场景2（响应性） 
o 交互型就绪 54 ticks，响应最差 
o 完全忽略优先级，高优先级的交互任务无法优先执行 
o CPU 背景最先创建，优先获得 CPU 
• 
场景3（饥饿） 
o 表现出“弱饥饿”（低优就绪 51），但这是创建顺序导致的 
o 随机调度不识别优先级，无法真正体现优先级差异 
总结： 行为不可预测，不适合生产环境。 
（2）RR（轮转调度） 
分析： 
 
• 
场景1（车队效应） 
o 短作业周转仅 4 ticks（最优），就绪等待 2 ticks 
o 轮转机制让短作业能快速穿插执行，无需等长作业完成 
o 长作业周转 42 ticks（较长），因为必须与其他进程轮流执行 
• 
场景2（响应性） 
o 交互型就绪 24 ticks（中等），因为 RR 不识别优先级 
o 虽然轮转保证公平，但无法优先调度高优先级任务 
o 对需要快速响应的交互场景不够理想 
• 
场景3（饥饿） 
o 中优和低优周转几乎相等（30 vs 32），完全公平 
o 高优周转 109 ticks（最长），因为工作量大且必须轮流执行 
o 无饥饿：所有进程公平获得 CPU 时间 
总结： 最公平的算法，但牺牲了优先级响应能力。 
（3）PRIORITY（优先级调度） 
分析： 
• 
场景1（车队效应） 
o 所有进程优先级相同（10），退化为类似 FCFS 的行为 

---PAGE---
13
 
o 短作业就绪 16 ticks，车队效应明显 
o 无法展现优先级调度的优势 
• 
场景2（响应性） 
o 交互型就绪 13 ticks，周转 213 ticks（最优） 
o 高优先级（3）的交互任务被优先调度 
o 这正是 PRIORITY 的设计目标：快速响应高优任务 
• 
场景3（饥饿） 
o 高优周转 36 ticks（很快），就绪 2 ticks 
o 低优就绪 55 ticks，必须等高优和中优执行完 
o 存在饥饿风险：若持续有高优任务，低优可能永远无法执行 
总结： 高优响应快，但可能导致低优饥饿。 
（4）FCFS（先来先服务） 
分析： 
• 
场景1（车队效应） 
o 短作业周转 8 ticks（中等），到达时间错开产生插队效果 
o 长作业被其他先到达的任务阻塞，周转差异大 
o 严格按创建顺序，后创建任务必须等待 
• 
场景2（响应性） 
o 交互型就绪 41 ticks，周转 263 ticks（最差） 
o 完全忽略优先级，CPU 背景先创建先执行 
o 对后到达的交互任务非常不友好 
• 
场景3（饥饿） 
o 低优周转 100 ticks（所有算法中最长） 
o 低优就绪 68 ticks，必须等所有先创建的任务 
o “创建顺序饥饿”：后创建任务永远被先创建任务阻塞 
总结： 严重的车队效应，对后到达任务不公平。 
（5）SML（静态多级队列） 
分析： 
• 
场景1（车队效应） 
o 所有进程优先级 10（中层），退化为 RR 行为 
o 短作业周转 4 ticks，与 RR 相同 
o 同层轮转避免车队效应 
• 
场景2（响应性） 
o 交互型就绪 10 ticks，周转 213 ticks（与 PRIORITY 并列最优） 
o 高优先级任务在高层队列，优先被调度 
o CPU 背景在低层，交互型 sleep 时它也能执行 

---PAGE---
14
 
• 
场景3（饥饿） 
o 高优周转 31 ticks（最快），因为独占高层队列 
o 低优就绪 58 ticks，存在跨层饥饿 
o 同层内轮转保证了层内公平 
总结： 兼顾优先级响应和同层公平，是最均衡的选择。 
5.2 核⼼问题分析 
（1）车队效应（Convoy Effect） 
定义： 短作业被长作业阻塞，导致短作业周转时间远超其实际运行时间。 
表现： 
• 
FCFS / PRIORITY / DEFAULT：短作业就绪等待长（16 ticks） 
• 
RR / SML：短作业就绪等待短（2 ticks） 
原因分析： 
• 
FCFS 按创建顺序，长作业先到则独占 CPU 
• 
PRIORITY 在同优先级时无法区分，表现类似 FCFS 
• 
RR / SML 通过时间片轮转，让短作业能穿插执行 
解决方案： 
• 
使用 RR 或 SML 调度 
• 
或使用最短作业优先（SJF）算法 
 
（2）响应性（Responsiveness） 
定义： 交互型任务获得 CPU 的速度。 
表现： 
• 
PRIORITY / SML：交互就绪 10–13 ticks（最优） 
• 
RR：交互就绪 24 ticks（中等） 
• 
FCFS：交互就绪 41 ticks（最差） 
原因分析： 
• 
PRIORITY / SML 识别优先级，高优任务优先调度 
• 
RR 公平轮转，不区分优先级 

---PAGE---
15
 
• 
FCFS 只看创建时间，后到达的交互任务必须等待 
解决方案： 
• 
交互系统应使用 PRIORITY 或 SML 
• 
为交互任务设置高优先级 
（3）饥饿（Starvation） 
定义： 低优先级任务长时间无法获得 CPU。 
表现： 
• 
RR：低优就绪 21 ticks，无饥饿 
• 
PRIORITY / SML：低优就绪 55–58 ticks，轻度饥饿 
• 
FCFS：低优就绪 68 ticks，严重饥饿 
原因分析： 
• 
RR 不识别优先级，所有进程公平执行 
• 
PRIORITY 严格按优先级，高优不结束则低优无法执行 
• 
FCFS 按创建顺序，后创建任务被阻塞 
解决方案：

需要公平性时使用 RR 
• 
使用动态优先级（老化机制）避免饥饿 
• 
SML 的同层轮转可部分缓解饥饿

1. 深入理解调度算法原理 
通过亲手实现五种调度算法，深刻理解了它们的选择逻辑和工作机制。特别是对轮
转调度的 lastIndex 状态记录、多级队列的分层策略有了直观的认识。 
2. 掌握操作系统内核编程 
在 xv6 内核中修改 proc.c，学会了如何在内核态添加新的调度策略，理解了调度器
与进程状态管理的关系。 
3. 学会设计测试场景 
针对车队效应、响应性、饥饿三个核心问题，设计了三个典型场景，能够有效区分
不同调度算法的特性差异。 
4. 理解调度算法的权衡 
没有“最好”的调度算法，只有“最适合”的调度算法。不同场景对公平性、响应性、
吞吐量有不同的需求，需要根据实际情况选择。

6.3 改进⽅向 
1. 动态优先级调整 
实现老化（Aging）机制，随时间提升等待进程的优先级，彻底避免饥饿。 
2. 多级反馈队列（MLFQ） 
根据进程行为动态调整所在队列层级，让 IO 密集型进程自动获得更高优先级。 
3. 完全公平调度（CFS） 
使用虚拟运行时间，保证每个进程获得公平的 CPU 份额，这是 Linux 的默认调度
器。 
4. 实时调度支持 
实现 EDF（最早截止时间优先）或 RMS（速率单调调度），支持硬实时任务。

6.4 实验结论 
本实验成功实现了五种经典调度算法，并通过三个精心设计的测试场景验证了它们的性能
特点。实验结果表明： 
1. RR 是最公平的算法，能完全避免饥饿，但无法识别优先级。 
2. PRIORITY 响应性最好，高优任务能快速执行，但可能导致低优任务饥饿。 
3. FCFS 实现最简单，但存在严重的车队效应，对后到达任务不友好。 
4. SML 是最均衡的选择，结合了优先级调度的响应性和轮转调度的公平性，适合大
多数通用场景。 
5. DEFAULT（随机调度）行为不可预测，仅适合测试和调试，不建议生产使用。 
调度算法的选择应根据具体应用场景的需求来决定。理解各算法的优缺点，是操作系统设
计和优化的重要基础。

// Default scheduler ------------------- 
struct proc *defaultScheduler(void) { 
  struct proc *p; 
  int i, rnd; 
   
  rnd = random(NPROC); 
  for (i = 0; i < NPROC; i++) { 
    p = ptable.proc + ((rnd + i) % NPROC);  
    if (p->state == RUNNABLE) return p; 
  } 
  return 0; 
} 
 
// Priority Scheduler ------------------- 
// 选择优先级值最小（优先级最高）的 RUNNABLE 进程 
struct proc *priorityScheduler() { 
  struct proc *p; 
  struct proc *highP = 0; 
   
  // 遍历进程表，找到优先级最高的进程 
  for(p = ptable.proc; p < &ptable.proc[NPROC]; p++) { 
    if(p->state != RUNNABLE) 
      continue; 
 
    // 如果还没找到或当前进程优先级更高（值更小） 
    if(highP == 0 || p->priority < highP->priority) { 
      highP = p; 
    } 
  } 
  return highP; 
} 
 
// FCFS Scheduler ----------------------- 
// 先来先服务：选择创建时间最早的 RUNNABLE 进程 
struct proc *fcfsScheduler() { 
  struct proc *p; 
  struct proc *earliest = 0; 
   
  for(p = ptable.proc; p < &ptable.proc[NPROC]; p++) { 
    if(p->state != RUNNABLE) 
      continue; 
    // 选择 ctime 最小（最早创建）的进程 
    if(earliest == 0 || p->ctime < earliest->ctime) { 
      earliest = p; 
    } 
  } 
  return earliest; 
}

// 轮转调度：循环遍历，轮流选择进程 
struct proc *rrScheduler() { 
  struct proc *p; 
  static int lastIndex = 0;  // 记录上次调度的位置 
  int i; 
   
  // 从上次位置的下一个开始查找 
  for(i = 0; i < NPROC; i++) { 
    int idx = (lastIndex + i) % NPROC; 
    p = &ptable.proc[idx]; 
    if(p->state == RUNNABLE) { 
      lastIndex = (idx + 1) % NPROC;  // 更新下次起始位置 
      return p; 
    } 
  } 
  return 0; 
} 
 
// SML Scheduler (Static Multi-Level Queue) 
// 静态多级队列：按优先级分3 层 
// 第1 层: priority 1-6 (高优先级) 
// 第2 层: priority 7-13 (中优先级)   
// 第3 层: priority 14-20 (低优先级) 
// 高层队列有进程时优先执行，同层内轮转 
struct proc *smlScheduler() { 
  struct proc *p; 
  static int lastIdx[3] = {0, 0, 0};  // 每层队列的轮转位置 
  int i, level; 
   
  // 按优先级从高到低遍历3 个队列 
  for(level = 0; level < 3; level++) { 
    for(i = 0; i < NPROC; i++) { 
      int idx = (lastIdx[level] + i) % NPROC; 
      p = &ptable.proc[idx]; 
       
      if(p->state != RUNNABLE) 
        continue; 
         
      // 判断进程属于哪个队列 
      int pLevel; 
      if(p->priority >= 1 && p->priority <= 6) 
        pLevel = 0;       // 高优先级队列 
      else if(p->priority >= 7 && p->priority <= 13) 
        pLevel = 1;       // 中优先级队列 
      else 
        pLevel = 2;       // 低优先级队列 
       
      // 只选择当前层的进程 
      if(pLevel == level) { 
        lastIdx[level] = (idx + 1) % NPROC; 
        return p; 
      } 
    }

26
 
  } 
  return 0; 
}

// 输出数字 
void output_int(int n) { 
  char buf[16]; 
  int i = 0, neg = 0; 
  if(n < 0) { neg = 1; n = -n; } 
  do { buf[i++] = '0' + (n % 10); n /= 10; } while(n > 0); 
  if(neg) buf[i++] = '-'; 
  char out[16]; 
  int j; 
  for(j = 0; j < i; j++) out[j] = buf[i-1-j]; 
  out[j] = 0; 
  output(out); 
} 
 
// CPU 密集型工作 
void cpu_work(int work) { 
  int i, j; 
  volatile int sum = 0; 
  for(i = 0; i < work; i++) { 
    for(j = 0; j < 100; j++) { 
      int x = i * j + (i ^ j); 
      x = (x << 1) ^ (x >> 1); 
      sum += x; 
    } 
  } 
} 
 
// IO 密集型工作 
void io_work(int rounds) { 
  int i, fd; 
  char buf[] = "io test\n"; 
  for(i = 0; i < rounds; i++) { 
    fd = open("io_test", O_CREATE | O_WRONLY); 
    if(fd >= 0) { 
      write(fd, buf, sizeof(buf) - 1); 
      close(fd); 
    } 
    sleep(15);  // 模拟IO 等待 
  } 
} 
 
// 交互型工作：短CPU + 频繁sleep（模拟用户输入等待） 
void interactive_work(int rounds) { 
  int i; 
  for(i = 0; i < rounds; i++) { 
    cpu_work(CPU_WORK / 50);  // 很短的CPU 计算 
    sleep(10);                 // 等待用户/IO 
  } 
}
