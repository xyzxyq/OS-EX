    \section{实验目的}
    
    本次实验围绕操作系统的核心主题——进程调度算法展开，旨在达成以下目标：
    
    \subsection{深入理解进程调度机制}
    学习操作系统中进程调度器的工作原理，理解调度器如何在多个就绪进程之间进行选择。掌握调度策略与调度算法的区别，以及不同调度算法对系统性能的影响。
    
    \subsection{掌握多种调度算法的原理与实现}
    研究并实现四种经典的进程调度算法：
    \begin{itemize}[label=\textbullet, itemsep=0pt]
        \item \textbf{优先级调度（Priority Scheduling）}：根据进程优先级选择执行，优先级高的进程优先获得CPU。
        \item \textbf{先来先服务（FCFS）}：按照进程到达就绪队列的先后顺序进行调度。
        \item \textbf{轮转调度（Round Robin）}：进程按照循环顺序轮流获得时间片执行。
        \item \textbf{静态多级队列（SML）}：将进程按优先级划分到不同队列，高优先级队列优先调度，队列内部使用轮转策略。
    \end{itemize}
    
    \subsection{设计调度算法评估框架}
    构建一个可切换的调度框架，支持在运行时动态切换调度算法。设计合理的测试方案，包含不同类型的负载（CPU密集型和IO密集型），对调度算法进行公平的性能对比。
    
    \subsection{掌握调度算法性能分析方法}
    学习进程运行时间统计方法，理解就绪时间、运行时间、休眠时间、周转时间等关键指标的含义。通过对比实验，分析不同调度算法在各项指标上的表现差异。

    \section{实验要求}
    
    \subsection{任务一：实现调度算法}
    在 \texttt{proc.c} 中编程实现以下四种调度算法：
    \begin{enumerate}
        \item \textbf{优先级调度（Priority Scheduling）}：选择优先级最高（数值最小）的就绪进程执行。
        \item \textbf{先来先服务（FCFS）}：选择创建时间最早的就绪进程执行。
        \item \textbf{轮转调度（Round Robin）}：按循环顺序公平地调度每个就绪进程。
        \item \textbf{静态多级队列（SML）}：按优先级将进程划分为多个队列，高优先级队列优先执行。
    \end{enumerate}

    在 \texttt{scheduler\_test.c} 中实现测试程序：
    \begin{enumerate}
        \item 创建 6 个进程，包含 3 个 CPU 密集型进程和 3 个 IO 密集型进程。
        \item 为不同类型的进程设置不同的优先级。
        \item 记录所有进程的运行过程，收集进程统计信息。
        \item 对比各调度算法在平均就绪时间、平均运行时间、平均休眠时间、平均周转时间上的结果。
    \end{enumerate}

    \subsubsection{就绪队列实现}
    
    为了提高调度效率，实现了真正的就绪队列数据结构，替代原有的"遍历进程表"方式。
    
    \textbf{队列与堆结构设计：}
    
    在 \texttt{proc.c} 中定义了不同的数据结构支持各种调度算法：
    \begin{itemize}
        \item \texttt{fcfsQueue}：用于 FCFS 和 RR 调度的先进先出队列（1个队列）
        \item \texttt{pHeap}：用于优先级调度的\textbf{最小堆}结构，时间复杂度 O(log n)
        \item \texttt{smlQueues[3]}：用于静态多级队列调度（3个队列：高/中/低）
    \end{itemize}
    
    \textbf{最小堆优化说明：}
    
    优先级调度采用最小堆而非多级队列实现，具有以下优势：
    \begin{itemize}
        \item 插入进程：O(log n)，通过 \texttt{siftUp()} 上浮操作维护堆性质
        \item 提取最高优先级进程：O(log n)，通过 \texttt{siftDown()} 下沉操作
        \item 堆的性质：父节点优先级 $\leq$ 子节点优先级（数值越小优先级越高）
    \end{itemize}
    
    \textbf{核心函数：}
    \begin{itemize}
        \item \texttt{enqueue(q, p)}：将进程 p 添加到队列 q 的尾部，时间复杂度 O(1)
        \item \texttt{dequeue(q)}：从队列 q 头部取出进程，时间复杂度 O(1)
        \item \texttt{addToReadyQueues(p)}：根据当前调度器类型，将进程添加到对应队列
    \end{itemize}

    \subsubsection{优先级调度算法（Priority Scheduling）}
    
    \textbf{算法原理：}
    
    优先级调度是一种基于进程重要性的抢占式或非抢占式调度算法。每个进程被分配一个优先级值，调度器总是选择优先级最高的就绪进程执行。在本实现中，优先级使用数值1-20表示，\textbf{数值越小表示优先级越高}。
    
    该算法的核心思想是：\textit{重要的任务应该优先得到CPU资源}。通过为不同类型的进程分配不同的优先级，系统可以确保关键任务（如系统服务、实时任务）能够快速响应，而次要任务（如后台批处理）则在资源空闲时执行。
    
    \textbf{实现策略：}
    
    本实现采用\textbf{最小堆}数据结构实现非抢占式优先级调度，具体设计如下：
    \begin{enumerate}[itemsep=2pt]
        \item 使用结构体 \texttt{priorityHeap} 存储就绪进程指针数组和堆大小
        \item 插入时调用 \texttt{heapInsert()}，将进程放入堆末尾后执行 \texttt{siftUp()} 上浮
        \item 提取时调用 \texttt{heapExtract()}，取出堆顶后将末尾元素放到堆顶，执行 \texttt{siftDown()} 下沉
        \item 堆顶始终是优先级最高（数值最小）的进程
    \end{enumerate}
    
    相比遍历进程表的 O(n) 实现，最小堆将提取操作优化到 O(log n)。
    \begin{enumerate}[itemsep=2pt]
        \item 遍历整个进程表，筛选出所有状态为 RUNNABLE 的就绪进程
        \item 维护一个候选进程指针 \texttt{highP}，初始值为 NULL
        \item 对每个就绪进程，比较其 \texttt{priority} 字段与当前候选进程
        \item 如果发现更高优先级的进程（数值更小），则更新候选进程指针
        \item 遍历完成后，返回优先级最高的进程
    \end{enumerate}
    
    \textbf{算法优势：}
    \begin{itemize}[itemsep=0pt]
        \item \textbf{响应快速}：高优先级进程可以立即获得CPU，适合实时系统
        \item \textbf{灵活性高}：可以根据实际需求动态调整进程优先级
        \item \textbf{实现简单}：只需一次遍历即可完成调度决策
    \end{itemize}
    
    \textbf{潜在问题：}
    \begin{itemize}[itemsep=0pt]
        \item \textbf{饥饿问题}：低优先级进程可能永远得不到执行机会
        \item \textbf{不够公平}：相同优先级的进程之间没有轮转机制
    \end{itemize}

        \item \textbf{返回结果}（第11行）：
        \begin{itemize}[itemsep=0pt]
            \item 返回优先级最高的进程指针 \texttt{highP}
            \item 如果没有就绪进程，\texttt{highP} 为 NULL (0)，调度器主循环会继续等待
        \end{itemize}
    \end{enumerate}
    
    \textbf{关键技术点：}
    \begin{itemize}[itemsep=2pt]
        \item \textbf{优先级比较}：使用 \texttt{<} 运算符而非 \texttt{>}，因为数值越小优先级越高
        \item \textbf{首次判断}：\texttt{highP == 0} 确保第一个就绪进程能被选中
        \item \textbf{时间复杂度}：O(n)，n为进程表大小（NPROC=64）
        \item \textbf{线程安全}：调用方（\texttt{scheduler()}）已持有 \texttt{ptable.lock}，无需额外加锁
    \end{itemize}
    
    \subsubsection{先来先服务调度算法（FCFS）}
    
    \textbf{算法原理：}
    
    先来先服务（First-Come First-Served）是最简单直观的调度算法，遵循"先到先得"的公平原则。进程按照进入就绪队列的时间顺序排队，调度器总是选择最早到达的进程执行，直到该进程执行完毕或主动放弃CPU。
    
    FCFS算法本质上是一个\textbf{非抢占式队列调度}，类似于日常生活中的"排队买票"——先来的人先得到服务，后来的人必须等待前面所有人处理完毕。
    
    \textbf{实现策略：}
    
    本实现通过比较进程的创建时间戳（\texttt{ctime}字段）来确定进程到达顺序：
    \begin{enumerate}[itemsep=2pt]
        \item 遍历进程表，筛选所有 RUNNABLE 状态的进程
        \item 维护候选进程指针 \texttt{firstP}，记录创建时间最早的进程
        \item 对每个就绪进程，比较其 \texttt{ctime} 与当前候选进程
        \item 选择 \texttt{ctime} 值最小（创建最早）的进程执行
        \item 该进程将持续运行直到完成或阻塞，\textbf{不会被时钟中断抢占}
    \end{enumerate}
    
    \textbf{非抢占式实现：}
    
    为实现真正的非抢占式 FCFS，在 \texttt{trap.c} 中修改了时钟中断处理逻辑：
    \begin{itemize}
        \item 当调度器为 FCFS (schedSelected == 2) 时，时钟中断不调用 \texttt{yield()}
        \item 进程只有主动调用 \texttt{sleep()}、\texttt{exit()} 等才会让出 CPU
    \end{itemize}
    
    \textbf{算法优势：}
    \begin{itemize}[itemsep=0pt]
        \item \textbf{实现简单}：无需复杂的数据结构和调度决策逻辑
        \item \textbf{公平性好}：所有进程按到达顺序依次执行，不会饥饿
        \item \textbf{可预测性强}：进程等待时间可以根据队列长度估算
    \end{itemize}
    
    \textbf{潜在问题：}
    \begin{itemize}[itemsep=0pt]
        \item \textbf{护航效应（Convoy Effect）}：一个长进程会阻塞后面所有短进程
        \item \textbf{平均等待时间长}：短作业可能因为前面的长作业而等待很久
        \item \textbf{不适合交互式系统}：无法优先响应用户交互请求
    \end{itemize}

    \subsubsection{轮转调度算法（Round Robin）}
    
    \textbf{算法原理：}
    
    轮转调度（Round Robin，简称RR）是一种\textbf{时间片轮转}的抢占式调度算法，被广泛应用于分时操作系统中。其核心思想是：将CPU时间划分为固定长度的时间片（time quantum），就绪队列中的进程按\textbf{循环顺序}依次获得一个时间片的执行机会。
    
    当一个进程的时间片用完后，即使它尚未完成，也会被迫让出CPU，回到就绪队列末尾等待下一轮调度。这种机制保证了所有进程都能\textit{公平地}获得CPU资源，不会出现某个进程长期占用CPU的情况。
    
    \textbf{实现策略：}
    
    本实现使用循环索引的方式模拟时间片轮转：
    \begin{enumerate}[itemsep=2pt]
        \item 使用静态变量 \texttt{lastIndex} 记录上次调度的进程在进程表中的位置
        \item 从 \texttt{lastIndex + 1} 开始向后查找下一个就绪进程
        \item 如果到达进程表末尾，则从头开始继续查找（循环特性）
        \item 找到第一个 RUNNABLE 进程后立即返回，不再比较优先级或到达时间
        \item 更新 \texttt{lastIndex}，为下次调度做准备
    \end{enumerate}
    
    \textbf{时间片设置：}在xv6中，时间片由时钟中断频率决定，默认为10ms。\textbf{只有 RR 调度器}在时钟中断时会强制调用 \texttt{yield()} 让出CPU，其他调度器（FCFS、PRIORITY、SML）均为非抢占式。
    
    \textbf{算法优势：}
    \begin{itemize}[itemsep=0pt]
        \item \textbf{公平性极佳}：所有进程获得相同的CPU时间配额
        \item \textbf{响应时间好}：交互式任务不会等待太久
        \item \textbf{无饥饿问题}：每个进程都保证在有限时间内得到调度
        \item \textbf{适合分时系统}：特别适合多用户、多任务环境
    \end{itemize}
    
    \textbf{潜在问题：}
    \begin{itemize}[itemsep=0pt]
        \item \textbf{上下文切换开销}：频繁切换进程会增加系统开销
        \item \textbf{时间片难以选择}：过长影响响应时间，过短增加开销
        \item \textbf{不区分优先级}：无法优先服务重要进程
    \end{itemize}

    \subsubsection{静态多级队列调度算法（SML）}
    
    \textbf{算法原理：}
    
    静态多级队列（Static Multi-Level Queue）是一种\textbf{混合型调度算法}，它巧妙地结合了优先级调度和轮转调度的优点。该算法的核心思想是：根据进程的优先级将其\textit{永久性地}分配到不同的就绪队列中，高优先级队列总是优先得到调度，而队列内部则采用轮转策略保证公平性。
    
    "静态"体现在进程一旦被分配到某个队列，其所属队列关系就固定不变；"多级"则体现在系统维护多个不同优先级的就绪队列。这种设计既保证了重要进程的响应速度，又避免了同等重要进程之间的不公平竞争。
    
    \textbf{队列划分策略：}
    
    本实现将进程按优先级划分为三个队列：
    \begin{itemize}[itemsep=2pt]
        \item \textbf{队列1（高优先级）}：priority 1-7 \quad （系统服务、实时任务）
        \item \textbf{队列2（中优先级）}：priority 8-14 \quad （普通用户进程）
        \item \textbf{队列3（低优先级）}：priority 15-20 \quad （后台批处理）
    \end{itemize}
    
     静态多级队列调度算法原理如图\ref{fig:SML}所示。
    
    \begin{figure}[H] 
    	\centering
    	\includegraphics[width=0.7\textwidth]{img/SML.png}
    	\caption{静态多级队列调度原理}
    	\label{fig:SML}
    \end{figure}
    
    \textbf{实现策略：}
    
    调度器按照以下严格顺序选择进程：
    \begin{enumerate}[itemsep=2pt]
        \item \textbf{优先调度队列1}：使用轮转方式从高优先级队列中选择进程
        \item 如果队列1为空，则调度队列2：同样使用轮转策略
        \item 如果队列2也为空，才调度队列3：继续使用轮转策略
        \item 每个队列维护独立的 \texttt{lastIdx} 索引，记录上次调度位置
        \item 当高优先级队列中有新进程就绪时，立即抢占低优先级队列的CPU
    \end{enumerate}
    
    \textbf{算法优势：}
    \begin{itemize}[itemsep=0pt]
        \item \textbf{兼顾效率与公平}：高优先级进程快速响应，同级进程公平竞争
        \item \textbf{调度开销较低}：只需遍历当前优先级队列，不必扫描全部进程
        \item \textbf{易于实现}：逻辑清晰，代码结构简单
        \item \textbf{灵活可扩展}：可根据需要增加或减少队列数量
    \end{itemize}
    
    \textbf{潜在问题：}
    \begin{itemize}[itemsep=0pt]
        \item \textbf{低优先级饥饿}：如果高优先级队列持续有进程，低优先级进程可能长期得不到调度
        \item \textbf{队列边界敏感}：优先级7和8的进程可能表现差异很大
        \item \textbf{缺乏动态调整}：无法根据进程行为自动提升或降低优先级
    \end{itemize}
    
    \textbf{改进空间：}可以引入\textit{老化机制}（aging），当低优先级进程等待时间过长时，临时提升其优先级，避免饥饿问题。

	\textbf{二、关键发现}
	\textbf{1. 优先级调度（PRIORITY）}
	\begin{itemize}[itemsep=2pt]
		\item \textbf{优势}：高优先级进程（PID 4-6）的就绪时间极短（1$\rightarrow$12$\rightarrow$23），体现了优先级调度的核心优势——重要任务快速响应
		\item \textbf{劣势}：低优先级IO进程的就绪时间显著增加（35-36 ticks），存在一定的不公平性
		\item \textbf{适用场景}：实时系统、关键任务优先的场景
	\end{itemize}
	\textbf{2. 先来先服务（FCFS）}
	\begin{itemize}[itemsep=2pt]
		\item \textbf{特征}：进程严格按创建顺序执行，就绪时间呈线性递增（1$\rightarrow$12$\rightarrow$24$\rightarrow$36）
		\item \textbf{护航效应明显}：CPU密集型进程先执行完毕后，IO密集型进程才开始，导致后续进程等待时间长
		\item \textbf{周转时间最长}：平均155 ticks，在四种算法中表现最差
		\item \textbf{适用场景}：简单批处理系统，对响应时间要求不高的场景
	\end{itemize}
	\textbf{3. 轮转调度（RR）}
	\begin{itemize}[itemsep=2pt]
		\item \textbf{公平性最佳}：所有进程的就绪时间分布均匀（23-25 ticks），没有明显的饥饿现象
		\item \textbf{周转时间最短}：平均147 ticks，得益于CPU和IO进程交替执行，减少了等待时间
		\item \textbf{休眠时间最少}：平均117 ticks，说明IO进程能够更及时地进入sleep状态
		\item \textbf{适用场景}：交互式分时系统，多用户环境
	\end{itemize}
	\textbf{4. 静态多级队列（SML）}
	\begin{itemize}[itemsep=2pt]
		\item \textbf{就绪时间最优}：平均20 ticks，在四种算法中表现最好
		\item \textbf{分层特征明显}：高优先级队列进程（PID 22-24）快速完成，中低优先级进程有序执行
		\item \textbf{综合性能优秀}：周转时间150 ticks，仅次于RR，但在优先级响应上更胜一筹
		\item \textbf{适用场景}：通用操作系统，需要兼顾效率与公平的场景
	\end{itemize}
	\textbf{三、进程类型差异分析}
	\textbf{CPU密集型进程}（优先级2/5/8）：
	\begin{itemize}[itemsep=1pt]
		\item 运行时间稳定在11-13 ticks
		\item 无休眠时间（sleep=0）
		\item 周转时间主要由就绪时间和运行时间决定
	\end{itemize}
	\textbf{IO密集型进程}（优先级10/14/18）：
	\begin{itemize}[itemsep=1pt]
		\item 运行时间极短（0-1 ticks）
		\item 休眠时间占主导（234-250 ticks）
		\item 周转时间主要由休眠时间决定，调度算法影响相对较小
	\end{itemize}

    \subsection{掌握了调度框架的设计方法}

    \subsection{深入理解了不同调度算法的特点}
    \begin{itemize}
        \item \textbf{优先级调度}：采用最小堆实现，时间复杂度 O(log n)；高优先级进程能快速响应，但可能导致低优先级进程饥饿
        \item \textbf{FCFS}：真正的非抢占式调度，进程运行直到主动让出 CPU；实现简单但可能导致护航效应
        \item \textbf{轮转调度}：唯一的抢占式调度，公平性好，适合交互式系统
        \item \textbf{静态多级队列}：结合了优先级和轮转的优点，在效率与公平之间取得平衡
    \end{itemize}
    
    \subsection{掌握了数据结构优化技术}
    在优先级调度中，我使用最小堆替代了传统的多级队列或线性遍历方式。堆的上浮（siftUp）和下沉（siftDown）操作确保了 O(log n) 的时间复杂度，这是一个重要的算法优化实践。

        // setpriority：修改指定进程的优先级
        // 参数：pid - 目标进程ID，priority - 新优先级值(1-20)
        // 返回值：0表示成功，-1表示失败
        int
        setpriority(int pid, int priority)
        {
            struct proc *p;          // 用于遍历进程表的指针
            int found = 0;           // 标志：是否找到目标进程
            
            // 步骤1：参数校验 - 优先级必须在[1, 20]范围内
            if(priority < 1 || priority > 20)
            return -1;
            
            // 步骤2：获取进程表锁，确保互斥访问
            acquire(&ptable.lock);
            
            // 步骤3：遍历进程表，查找目标进程
            for(p = ptable.proc; p < &ptable.proc[NPROC]; p++){
                if(p->pid == pid){
                    p->priority = priority;  // 修改优先级
                    found = 1;
                    break;
                }
            }
            
            // 步骤4：释放进程表锁
            release(&ptable.lock);
            
            // 步骤5：返回结果
            return found ? 0 : -1;
        }

    \subsubsection{B.2 proc.c - getptable函数}

        // getptable：将内核进程表信息复制到用户空间
        // 参数：ubuf - 用户空间缓冲区地址，size - 缓冲区大小
        // 返回值：0表示成功，-1表示失败
        int 
        getptable(void *ubuf, int size)
        {
            struct proc *p;              // 进程表遍历指针
            struct proc_info pi;         // 临时变量，用于构造进程信息
            char *uptr = (char*)ubuf;    // 用户缓冲区指针
            int i = 0;                   // 进程计数器
            
            // 步骤1：缓冲区大小检查
            if(size < NPROC * sizeof(struct proc_info))
            return -1;
            
            // 步骤2：获取进程表锁
            acquire(&ptable.lock);
            
            // 步骤3：遍历进程表
            for(p = ptable.proc; p < &ptable.proc[NPROC]; p++){
                // 清零临时结构体
                memset(&pi, 0, sizeof(pi));
                
                // 如果槽位正在使用，填充信息
                if(p->state != UNUSED){
                    pi.pid = p->pid;
                    pi.ppid = (p->parent) ? p->parent->pid : -1; 
                    pi.priority = p->priority;
                    pi.mem_size = p->sz;
                    pi.state = p->state;
                    safestrcpy(pi.name, p->name, sizeof(pi.name));
                }
                
                // 步骤4：复制到用户空间
                if(copyout(myproc()->pgdir, 
                (uint)(uptr + i * sizeof(struct proc_info)), 
                (char*)&pi, sizeof(pi)) < 0){
                    release(&ptable.lock);
                    return -1;
                }
                i++;
            }
            
            // 步骤5：释放锁并返回
            release(&ptable.lock);
            return 0;
        }
    \end{codeblock}

        // sem_init：初始化一个信号量
        // 参数：sem - 信号量ID(0-31)，value - 信号量初始值
        // 返回值：0表示成功，-1表示失败
        int
        sem_init(int sem, int value)
        {
            // 步骤1：参数校验
            if(sem < 0 || sem >= 32)
            return -1;
            
            // 步骤2：获取该信号量的锁
            acquire(&sema[sem].lock);
            
            // 步骤3：检查是否已被初始化
            if(sema[sem].active == 1) {
                release(&sema[sem].lock);
                return -1;  // 已在使用，不允许重复初始化
            }
            
            // 步骤4：初始化信号量
            sema[sem].value = value;  // 设置初始值
            sema[sem].active = 1;     // 标记为活跃状态
            
            // 步骤5：释放锁
            release(&sema[sem].lock);
            
            return 0;
        }

    \subsubsection{D.3 proc.c - sem\_wait函数(P操作)}
    
    \begin{codeblock}{sem\_wait实现}
        // sem_wait：P操作，申请资源，资源不足则阻塞
        // 参数：sem - 信号量ID，count - 需要申请的资源数量
        // 返回值：0表示成功，-1表示失败
        int 
        sem_wait(int sem, int count)
        {
            // 步骤1：参数校验
            if(sem < 0 || sem >= 32)
            return -1;
            
            // 步骤2：获取信号量锁
            acquire(&sema[sem].lock);
            
            // 步骤3：检查是否处于活跃状态
            if(sema[sem].active == 0){
                release(&sema[sem].lock);
                return -1;
            }
            
            // 步骤4：循环检查资源是否足够（核心逻辑）
            // 使用while而非if，防止虚假唤醒
            while(sema[sem].value < count){
                // 资源不足，进程进入睡眠
                // sleep的参数1：睡眠通道（使用信号量地址）
                // sleep的参数2：当前持有的锁
                // sleep会原子性地释放锁并进入SLEEPING状态
                sleep(&sema[sem], &sema[sem].lock);
                
                // 被唤醒后，回到while开头重新检查条件
                
                // 防御性检查：信号量是否在睡眠期间被销毁
                if(sema[sem].active == 0){
                    release(&sema[sem].lock);
                    return -1;
                }
            }
            
            // 步骤5：资源充足，消耗资源
            sema[sem].value -= count;
            
            // 步骤6：记账，用于进程退出时的自动资源回收
            myproc()->sem_held[sem] += count;
            
            // 步骤7：释放锁
            release(&sema[sem].lock);
            
            return 0;
        }
    \end{codeblock}
    
    \subsubsection{D.4 proc.c - sem\_signal函数(V操作)}
    
    \begin{codeblock}{sem\_signal实现}
        // sem_signal：V操作，释放资源并唤醒等待者
        // 参数：sem - 信号量ID，count - 需要释放的资源数量
        // 返回值：0表示成功，-1表示失败
        int 
        sem_signal(int sem, int count)
        {
            // 步骤1：参数校验
            if(sem < 0 || sem >= 32)
            return -1;
            
            // 步骤2：获取信号量锁
            acquire(&sema[sem].lock);
            
            // 步骤3：检查活跃状态
            if(sema[sem].active == 0){
                release(&sema[sem].lock);
                return -1;
            }
            
            // 步骤4：释放资源，增加信号量的值
            sema[sem].value += count;
            
            // 步骤5：销账，减少当前进程的资源持有计数
            if(myproc()->sem_held[sem] >= count) {
                myproc()->sem_held[sem] -= count;
            } else {
                // 防御性处理：持有计数不足，清零
                myproc()->sem_held[sem] = 0;
            }
            
            // 步骤6：唤醒所有等待该信号量的进程
            // wakeup将所有在该通道上睡眠的进程状态改为RUNNABLE
            wakeup(&sema[sem]);
            
            // 步骤7：释放锁
            release(&sema[sem].lock);
            
            return 0;
        }
    \end{codeblock}

    \subsection{附录E：信号量测试程序}
    
    \subsubsection{E.1 sem\_test.c - 完整实现}
    
    \begin{codeblock}{sem\_test.c}
        #include "types.h"
        #include "stat.h"
        #include "user.h"
        #include "fcntl.h"
        
        // 测试参数定义
        #define NUM_CHILDREN 10              // 并发子进程数量
        #define TARGET_COUNT_PER_CHILD 50    // 每个子进程的循环次数
        #define COUNTER_FILE "counter"       // 共享计数器文件名
        #define SEM_ID 0                     // 使用0号信号量
        
        // test_counter：信号量互斥测试函数
        void
        test_counter()
        {
            int i, j;
            int fd;
            int val;
            
            // ===== 第一部分：初始化 =====
            
            // 步骤1：创建共享计数器文件并写入初始值0
            fd = open(COUNTER_FILE, O_CREATE | O_RDWR);
            if(fd < 0){
                printf(1, "Error: create counter file failed\n");
                exit();
            }
            val = 0;
            write(fd, &val, sizeof(int));  // 写入4字节整数
            close(fd);
            
            // 步骤2：初始化互斥信号量（初始值为1，作为互斥锁）
            if(sem_init(SEM_ID, 1) < 0){
                printf(1, "Error: sem_init failed\n");
                exit();
            }
            
            printf(1, "Starting %d children, each incrementing %d times...\n", 
            NUM_CHILDREN, TARGET_COUNT_PER_CHILD);
            
            // ===== 第二部分：创建并发子进程 =====
            
            for(i = 0; i < NUM_CHILDREN; i++){
                int pid = fork();
                if(pid < 0){
                    printf(1, "fork failed\n");
                    exit();
                }
                
                if(pid == 0){
                    // --- 子进程代码 ---
                    for(j = 0; j < TARGET_COUNT_PER_CHILD; j++){
                        
                        // P操作：申请进入临界区
                        if(sem_wait(SEM_ID, 1) < 0){
                            printf(1, "Child: sem_wait failed\n");
                            exit();
                        }
                        
                        // ========== 临界区开始 ==========
                        
                        // 读取当前计数值
                        fd = open(COUNTER_FILE, O_RDONLY);
                        if(fd < 0){
                            printf(1, "Child: open read failed\n");
                            exit();
                        }
                        if(read(fd, &val, sizeof(int)) != sizeof(int)){
                            printf(1, "Child: read failed\n");
                            exit();
                        }
                        close(fd);
                        
                        // 更新计数值（加1）
                        val++;
                        
                        // 写回新值
                        fd = open(COUNTER_FILE, O_WRONLY); 
                        if(fd < 0){
                            printf(1, "Child: open write failed\n");
                            exit();
                        }
                        if(write(fd, &val, sizeof(int)) != sizeof(int)){
                            printf(1, "Child: write failed\n");
                            exit();
                        }
                        close(fd);
                        
                        // ========== 临界区结束 ==========
                        
                        // V操作：离开临界区
                        if(sem_signal(SEM_ID, 1) < 0){
                            printf(1, "Child: sem_signal failed\n");
                            exit();
                        }
                    }
                    
                    exit();  // 子进程完成后退出
                }
            }
            
            // ===== 第三部分：等待子进程并验证结果 =====
            
            // 父进程等待所有子进程退出
            for(i = 0; i < NUM_CHILDREN; i++){
                wait();
            }
            
            // 读取最终计数值
            fd = open(COUNTER_FILE, O_RDONLY);
            read(fd, &val, sizeof(int));
            close(fd);
            
            printf(1, "Final counter value: %d\n", val);
            
            // 验证结果（期望值：10 × 50 = 500）
            if(val == NUM_CHILDREN * TARGET_COUNT_PER_CHILD){
                printf(1, "TEST PASSED!\n");
            } else {
                printf(1, "TEST FAILED! Expected %d\n", 
                NUM_CHILDREN * TARGET_COUNT_PER_CHILD);
            }
            
            // ===== 第四部分：清理资源 =====
            
            sem_destroy(SEM_ID);    // 销毁信号量
            unlink(COUNTER_FILE);   // 删除测试文件
            
            return;
        }
        
        int
        main(int argc, char *argv[])
        {
            test_counter();
            return 0;
        }
    \end{codeblock}
