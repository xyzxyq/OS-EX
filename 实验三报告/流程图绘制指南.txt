# 实验三报告流程图绘制指南

本文档详细描述了实验三报告中需要绘制的8张流程图及其绘制思路。

================================================================================
## 流程图1：调度框架设计流程图 (sched_framework.drawio)
================================================================================

### 目标
展示可扩展调度框架的整体架构设计，说明如何通过函数指针实现调度算法的动态切换。

### 流程图类型
结构图 + 流程图混合

### 核心节点设计

```
[开始] 系统初始化
    ↓
[数据结构] schedulerName[] 数组
    - "DEFAULT"
    - "PRIORITY" 
    - "FCFS"
    - "RR"
    - "SML"
    ↓
[数据结构] schedulerFunction[] 函数指针数组
    - defaultScheduler()
    - priorityScheduler()
    - fcfsScheduler()
    - rrScheduler()
    - smlScheduler()
    ↓
[变量] ready_process 函数指针
    - 指向当前使用的调度函数
    ↓
[系统调用] setscheduler(sid)
    ↓
[判断] sid 是否有效?
    ├─ 否 → 返回 -1
    └─ 是 → 更新 ready_process = schedulerFunction[sid]
              更新 schedSelected = sid
              返回 sid
```

### 建议配色
- 数据结构：浅蓝色
- 函数/操作：浅绿色
- 判断：浅黄色菱形
- 开始/结束：椭圆形

## 流程图2：调度器主循环流程图 (scheduler_main.drawio)
================================================================================

### 目标
展示 scheduler() 函数的主循环逻辑，说明CPU如何不断选择进程执行。

### 流程图类型
标准流程图

### 核心节点设计

```
[开始] scheduler()
    ↓
[初始化] c = mycpu()
         c->proc = 0
    ↓
┌─→ [操作] sti() 开启中断
│       ↓
│   [操作] acquire(&ptable.lock)
│       ↓
│   [操作] acquire(&schedulerlock)
│       ↓
│   [调用] p = (*ready_process)()
│          调用当前调度算法
│       ↓
│   [操作] release(&schedulerlock)
│       ↓
│   [判断] p != 0 ?
│       ├─ 否 → [操作] release(&ptable.lock) ─┐
│       │                                      │
│       └─ 是 ↓                                │
│       [操作] c->proc = p                     │
│              switchuvm(p)                    │
│              p->state = RUNNING              │
│       ↓                                      │
│       [操作] swtch(&c->scheduler, p->context)│
│              上下文切换到进程p               │
│       ↓                                      │
│       [操作] switchkvm()                     │
│              c->proc = 0                     │
│       ↓                                      │
│       [操作] release(&ptable.lock) ←─────────┘
│       ↓
└───────┘ (无限循环)
```

### 关键说明
- 强调这是一个无限循环
- 标注锁的获取和释放配对
- 突出 ready_process 函数指针调用

## 流程图3：优先级调度算法流程图 (priority_scheduler.drawio)
================================================================================

### 目标
展示如何遍历进程表选择优先级最高的就绪进程。

### 流程图类型
标准流程图

### 核心节点设计

```
[开始] priorityScheduler()
    ↓
[初始化] highP = 0 (候选进程指针)
    ↓
[初始化] p = ptable.proc (遍历指针)
    ↓
┌─→ [判断] p < &ptable.proc[NPROC] ?
│       ├─ 否 → [返回] return highP
│       │
│       └─ 是 ↓
│   [判断] p->state == RUNNABLE ?
│       ├─ 否 → p++ ─────────────────┐
│       │                            │
│       └─ 是 ↓                      │
│   [判断] highP == 0 或             │
│          p->priority < highP->priority ?
│       ├─ 否 → p++ ─────────────────┤
│       │                            │
│       └─ 是 ↓                      │
│       [赋值] highP = p             │
│       ↓                            │
│       p++ ←────────────────────────┘
│       ↓
└───────┘
```

### 关键说明
- priority 值越小，优先级越高
- 遍历完成后返回优先级最高的进程
- 如果没有就绪进程，返回 0

## 流程图4：FCFS调度算法流程图 (fcfs_scheduler.drawio)
================================================================================

### 目标
展示如何选择创建时间最早的就绪进程。

### 流程图类型
标准流程图

### 核心节点设计

```
[开始] fcfsScheduler()
    ↓
[初始化] firstP = 0 (最早进程指针)
    ↓
[初始化] p = ptable.proc
    ↓
┌─→ [判断] p < &ptable.proc[NPROC] ?
│       ├─ 否 → [返回] return firstP
│       │
│       └─ 是 ↓
│   [判断] p->state == RUNNABLE ?
│       ├─ 否 → p++ ─────────────────┐
│       │                            │
│       └─ 是 ↓                      │
│   [判断] firstP == 0 或            │
│          p->ctime < firstP->ctime ?│
│       ├─ 否 → p++ ─────────────────┤
│       │                            │
│       └─ 是 ↓                      │
│       [赋值] firstP = p            │
│       ↓                            │
│       p++ ←────────────────────────┘
│       ↓
└───────┘
```

### 关键说明
- ctime 是进程创建时间
- 选择 ctime 最小（最早创建）的进程
- 结构与优先级调度类似，只是比较字段不同

## 流程图5：轮转调度算法流程图 (rr_scheduler.drawio)
================================================================================

### 目标
展示如何使用静态变量实现循环调度。

### 流程图类型
标准流程图

### 核心节点设计

```
[开始] rrScheduler()
    ↓
[说明] static lastIndex = 0
       (静态变量，记录上次位置)
    ↓
[初始化] i = 0
    ↓
┌─→ [判断] i < NPROC ?
│       ├─ 否 → [返回] return 0
│       │        (没有就绪进程)
│       │
│       └─ 是 ↓
│   [计算] lastIndex = (lastIndex + 1) % NPROC
│          (循环递增索引)
│       ↓
│   [获取] p = &ptable.proc[lastIndex]
│       ↓
│   [判断] p->state == RUNNABLE ?
│       ├─ 否 → i++ ─────────────────┐
│       │                            │
│       └─ 是 ↓                      │
│       [返回] return p              │
│              找到就绪进程          │
│       ↓                            │
│       i++ ←────────────────────────┘
│       ↓
└───────┘
```

### 关键说明
- 关键点：lastIndex 是 static 变量，下次调用保留上次值
- 使用取模运算实现循环
- 最多遍历 NPROC 次

## 流程图6：静态多级队列调度算法流程图 (sml_scheduler.drawio)
================================================================================

### 目标
展示三级队列的优先级调度和队列内轮转机制。

### 流程图类型
分层流程图（建议使用泳道或分区）

### 核心节点设计

```
[开始] smlScheduler()
    ↓
[说明] static lastIdx[3] = {0,0,0}
       (三个队列各自的轮转索引)
    ↓
╔════════════════════════════════════╗
║ 阶段1：高优先级队列 (priority 1-7) ║
╚════════════════════════════════════╝
    ↓
[循环] 遍历进程表 (i: 0 → NPROC)
    ├─ lastIdx[0] = (lastIdx[0]+1) % NPROC
    ├─ p = &ptable.proc[lastIdx[0]]
    └─ [判断] p->state==RUNNABLE 且 priority∈[1,7] ?
           ├─ 是 → [返回] return p
           └─ 否 → 继续循环
    ↓ (队列1无就绪进程)
╔════════════════════════════════════╗
║ 阶段2：中优先级队列 (priority 8-14)║
╚════════════════════════════════════╝
    ↓
[循环] 遍历进程表 (i: 0 → NPROC)
    ├─ lastIdx[1] = (lastIdx[1]+1) % NPROC
    ├─ p = &ptable.proc[lastIdx[1]]
    └─ [判断] p->state==RUNNABLE 且 priority∈[8,14] ?
           ├─ 是 → [返回] return p
           └─ 否 → 继续循环
    ↓ (队列2无就绪进程)
╔════════════════════════════════════════╗
║ 阶段3：低优先级队列 (priority 15-20)   ║
╚════════════════════════════════════════╝
    ↓
[循环] 遍历进程表 (i: 0 → NPROC)
    ├─ lastIdx[2] = (lastIdx[2]+1) % NPROC
    ├─ p = &ptable.proc[lastIdx[2]]
    └─ [判断] p->state==RUNNABLE 且 priority∈[15,20] ?
           ├─ 是 → [返回] return p
           └─ 否 → 继续循环
    ↓ (所有队列都无就绪进程)
[返回] return 0
```

### 关键说明
- 三个队列按优先级划分，高优先级队列先调度
- 每个队列内部使用独立的轮转索引
- 建议用不同颜色区分三个优先级区域

## 流程图7：测试程序设计流程图 (scheduler_test.drawio)
================================================================================

### 目标
展示测试程序如何创建进程、设置优先级、收集统计信息。

### 流程图类型
包含父子进程的流程图（建议使用泳道）

### 核心节点设计

```
╔═══════════════════════════════════════════════════════════════╗
║                     父进程 (测试主程序)                        ║
╚═══════════════════════════════════════════════════════════════╝

[开始] run_scheduler_test(sched_id)
    ↓
[操作] setscheduler(sched_id)
       设置调度算法
    ↓
[循环] for i = 0 to 5:
    ↓
[操作] pid = fork()
    ↓
[判断] pid == 0 ?
    ├─ 是 → ═══════════════════════════
    │        进入子进程逻辑 (见下方)
    │       ═══════════════════════════
    │
    └─ 否 → [记录] pids[i] = pid
              ↓
         继续循环
    ↓ (创建完6个进程)
[循环] for i = 0 to 5:
    ↓
[操作] wait2(&retime[i], &rutime[i], &stime[i])
       等待子进程并收集统计信息
    ↓
[操作] print_statistics(...)
       输出统计结果
    ↓
[结束]

╔═══════════════════════════════════════════════════════════════╗
║                     子进程逻辑                                 ║
╚═══════════════════════════════════════════════════════════════╝

[判断] i < 3 ?
    ├─ 是 → [CPU密集型进程]
    │       setpriority(getpid(), 2/5/8)
    │       ↓
    │       cpu_intensive(i)
    │       大量嵌套循环计算
    │
    └─ 否 → [IO密集型进程]
            setpriority(getpid(), 10/14/18)
            ↓
            io_intensive(i)
            循环: 少量计算 + sleep(5)
    ↓
[退出] exit()
```

### 关键说明
- 使用泳道区分父进程和子进程
- 标注优先级分配策略：CPU密集型(2,5,8)，IO密集型(10,14,18)
- 强调 wait2() 收集三个时间统计字段

## 流程图8：wait2 系统调用流程图 (wait2.drawio)
================================================================================

### 目标
展示 wait2() 如何扩展 wait() 以返回进程统计信息。

### 流程图类型
标准流程图

### 核心节点设计

```
[开始] wait2(retime, rutime, stime)
    ↓
[操作] acquire(&ptable.lock)
    ↓
┌─→ [初始化] havekids = 0
│       ↓
│   [循环开始] 遍历 ptable.proc
│       ↓
│   [判断] p->parent != myproc() ?
│       ├─ 是 → 继续下一个进程 ─────────┐
│       │                              │
│       └─ 否 ↓                        │
│       [赋值] havekids = 1            │
│       ↓                              │
│   [判断] p->state == ZOMBIE ?        │
│       ├─ 否 → 继续下一个进程 ────────┤
│       │                              │
│       └─ 是 ↓                        │
│       ╔══════════════════════════╗   │
│       ║ 收集统计信息 (关键步骤)   ║   │
│       ║ *retime = p->retime      ║   │
│       ║ *rutime = p->rutime      ║   │
│       ║ *stime  = p->stime       ║   │
│       ╚══════════════════════════╝   │
│       ↓                              │
│       [操作] pid = p->pid            │
│              回收进程资源            │
│              (kfree, freevm等)       │
│       ↓                              │
│       [操作] release(&ptable.lock)   │
│       ↓                              │
│       [返回] return pid              │
│       ↓                              │
│   [循环结束] ←────────────────────────┘
│       ↓
│   [判断] !havekids || myproc()->killed ?
│       ├─ 是 → [操作] release(&ptable.lock)
│       │       ↓
│       │       [返回] return -1
│       │
│       └─ 否 ↓
│       [操作] sleep(myproc(), &ptable.lock)
│              等待子进程状态变化
│       ↓
└───────┘ (回到循环开始)
```

### 关键说明
- 用高亮框标注收集统计信息的关键步骤
- 这是与普通 wait() 的主要区别
- 强调循环等待直到有子进程退出

## 绘制建议汇总
================================================================================

### 统一风格建议
- 开始/结束：椭圆形，深蓝色边框
- 操作/处理：矩形，浅绿色填充
- 判断/条件：菱形，浅黄色填充
- 数据/变量：平行四边形，浅蓝色填充
- 循环：六边形或带循环标记的矩形

### 文件命名建议
1. sched_framework.drawio.pdf  - 调度框架设计
2. scheduler_main.drawio.pdf   - 调度器主循环
3. priority_scheduler.drawio.pdf - 优先级调度
4. fcfs_scheduler.drawio.pdf   - FCFS调度
5. rr_scheduler.drawio.pdf     - 轮转调度
6. sml_scheduler.drawio.pdf    - 静态多级队列调度
7. scheduler_test.drawio.pdf   - 测试程序设计
8. wait2.drawio.pdf            - wait2系统调用

### 尺寸建议
- 建议画布宽度：800-1000px
- 导出为 PDF 格式以保证清晰度
- 每个节点文字简洁，关键术语使用等宽字体
